![:일:](https://a.slack-edge.com/production-standard-emoji-assets/14.0/google-medium/0031-fe0f-20e3.png) Docker 컨테이너 접속  

docker exec -it <컨테이너이름> bash

- 여기서 `<컨테이너이름>`은 예시: `cogirihub`
- **왜 필요한가?** CSV를 컨테이너 안으로 복사하거나, psql CLI를 실행하려면 컨테이너 내부 환경에 접근해야 합니다.

![:둘:](https://a.slack-edge.com/production-standard-emoji-assets/14.0/google-medium/0032-fe0f-20e3.png) PostgreSQL 접속  
컨테이너 안에서:  

psql -U <사용자명> -d <데이터베이스명>

예시:  

psql -U cogirihub -d cogirihub

- PostgreSQL CLI(`psql`)로 들어가야 SQL 명령 실행 가능

![:셋:](https://a.slack-edge.com/production-standard-emoji-assets/14.0/google-medium/0033-fe0f-20e3.png) 테이블 생성  
CSV 데이터를 넣을 **테이블을 먼저 만들어야 함**. 예:  

CREATE TABLE weather (
    id SERIAL PRIMARY KEY,
    date DATE,
    avg_temp FLOAT,
    max_temp FLOAT,
    max_temp_time TIME,
    min_temp FLOAT,
    min_temp_time TIME,
    diff_temp FLOAT,
    precipitation FLOAT
);

- 여기서 **컬럼 타입**이 CSV 값과 맞는지 확인 필요 (숫자, 시간, NULL 처리 등)
- 생략하면 CSV 삽입시 타입 에러 발생 가능

![:넷:](https://a.slack-edge.com/production-standard-emoji-assets/14.0/google-medium/0034-fe0f-20e3.png) CSV 파일 컨테이너 안으로 복사  
호스트(내 컴퓨터)에서:  

docker cp "C:\path\to\weather.csv" <컨테이너이름>:/weather.csv

- `/weather.csv`는 컨테이너 내부 경로
- **생략하면** 컨테이너 안에서 CSV를 찾을 수 없어 삽입 실패

![:다섯:](https://a.slack-edge.com/production-standard-emoji-assets/14.0/google-medium/0035-fe0f-20e3.png) CSV 데이터 테이블에 삽입  
컨테이너 안 psql에서:  

\copy weather(date, avg_temp, max_temp, max_temp_time, min_temp, min_temp_time, diff_temp, precipitation) FROM '/weather.csv' DELIMITER ',' CSV HEADER;

- `\copy`는 PostgreSQL에서 **컨테이너 내부 파일을 테이블로 복사**할 때 사용
- `CSV HEADER` 옵션: 첫 줄을 컬럼명으로 인식
- **주의점**: CSV의 컬럼 순서와 테이블 컬럼 순서가 정확히 맞아야 함

![:여섯:](https://a.slack-edge.com/production-standard-emoji-assets/14.0/google-medium/0036-fe0f-20e3.png) 데이터 확인  

SELECT * FROM weather ORDER BY id;

- 삽입된 데이터가 제대로 들어갔는지 확인
- 원하는 줄 수와 값이 정확히 나오는지 체크

![:열쇠:](https://a.slack-edge.com/production-standard-emoji-assets/14.0/google-medium/1f511.png) 핵심 포인트 (생략된 부분)  

1. CSV 파일 컬럼과 테이블 컬럼 타입 및 순서 일치 필요
2. 빈 값 → `NULL` 처리 필요
3. 컨테이너 내부 경로 확인 필요 (`docker cp`에서 올린 경로)
4. `\copy` 사용 시 CSV 옵션 정확히 명시 (`DELIMITER`, `CSV HEADER`)
5. 테이블 생성 후, 필요하면 기존 데이터 삭제 (`TRUNCATE`)

## 실제 문제

${변수명} 치환이 env_file의 내용을 참조하지 않기 때문입니다.

### 실행 순서

1. 파싱 시점 (호스트에서):

- docker-compose.yaml 파일을 읽습니다

- ${변수명} 치환을 처리합니다

- 참조 대상: 호스트 환경 변수 또는 docker-compose.yaml과 같은 디렉토리의 .env 파일

- env_file의 내용은 이 시점에서 사용되지 않습니다

1. 런타임 (컨테이너 시작):

- 컨테이너가 시작될 때

- env_file의 내용이 컨테이너 내부 환경 변수로 주입됩니다

- environment 섹션의 값들이 컨테이너에 설정됩니다 (이미 치환된 값)


docker-compose.yaml 파싱 (호스트)
  ├─ ${UPSTASH_REDIS_HOST} 치환 시도
  │   └─ 참조: 호스트 .env 파일 (docker-compose.yaml과 같은 디렉토리)
  │   └─ 참조 안함: env_file의 ../.env 파일 ❌
  │
  └─ 결과: SPRING_REDIS_HOST="" (비어있음)

컨테이너 시작 (런타임)
  ├─ env_file: - ../.env 읽기
  │   └─ 컨테이너 내부에 환경 변수 주입
  │
  └─ environment: 이미 치환된 값들 주입
      └─ SPRING_REDIS_HOST="" (이미 비어있음)


${변수명} 치환: 호스트 측 (docker-compose 프로세스)
  └─ docker-compose.yaml 파일 파싱
  └─ 호스트 환경에서 실행
  
env_file: 컨테이너 측 (Docker 데몬)
  └─ 컨테이너 시작 시
  └─ 컨테이너 내부 환경 변수 설정

### 설계 철학

- ${변수명} 치환: 템플릿화와 구성 파일의 동적 생성(호스트 측)

- env_file: 런타임 환경 변수 주입(컨테이너 측)



## 결론

순서가 엇갈려서가 아니라, ${변수명} 치환이 env_file을 참조하지 않기 때문입니다. ${변수명} 치환은 호스트의 환경 변수나 docker-compose.yaml과 같은 디렉토리의 .env 파일에서만 값을 읽습니다.
