# JPA — 자바와 데이터베이스를 연결하는 다리

자바 코드와 데이터베이스(테이블)는 원래 서로 다른 세계입니다. JPA는 이 둘을 이어 주는 다리 역할을 합니다. 저는 JPA를 **"자바와 DB를 연결해 주는, 도커처럼 중간에서 거들어 주는 도구"** 정도로 이해하고 출발했습니다.

## 2. 매핑(Mapping) — 두 언어를 연결하기

매핑은 서로 다른 두 영역을 연결하는 작업입니다. 리액트에서 말하는 **바인딩(binding)** 과 같은 개념이라고 보면 됩니다.

## 3. 요청과 응답의 흐름 — DTO와 VO

데이터는 한 방향으로 흐르지 않습니다. 요청과 응답이 서로 반대 방향으로 오갑니다.

```
리퀘스트(요청) DTO
------------------->
컨트롤러 → 서비스 → 레포지토리 → 엔티티
<-------------------
리스폰스(응답) VO
```

## 4. 세계관의 확장 — 파이프라인에서 테이블 연결로

예전에 자바만 사용할 때는 파이프라인이 비교적 소규모였습니다. JPA가 들어오면서 이 연결이 DB의 테이블까지 확장됩니다. 엔티티를 이용해 **키 값으로 테이블끼리 서로 연결**되기 때문입니다.

예를 들어 `player`, `team`, `stadium`이라는 엔티티가 각각 있을 때, 이들을 단방향 또는 양방향으로 연결합니다.

> **파이프라인이 단방향이라면, 테이블 연결은 양방향까지 가능합니다.**

개발에서 꼭 기억해야 할 두 가지 핵심은 다음과 같습니다.

- **부모 관계(상속 관계)와 종속 관계**
- 그 관계를 이어 주는 **연결선의 역할**

## 5. JPQL — SQL과 달라지는 문법

SQL에서 쓰던 쿼리는 자바(JPA)에서 문법이 달라집니다. SQL에서는 `JOIN`으로 키 값을 기준으로 테이블을 합치지만, JPA에서는 JPQL 문법을 사용합니다.

## 참고 — 스칼라와 벡터

테이블 데이터를 다룰 때 자주 등장하는 스칼라/벡터 개념을 정리하면 다음과 같습니다.

| 구분              | 스칼라 (Scalar) | 벡터 (Vector)       |
| --------------- | ------------ | ----------------- |
| **차원**          | 0차원          | 1차원               |
| **구성요소**        | 단일 값         | 여러 스칼라 값          |
| **예시 (Python)** | `5`          | `[1, 2, 3]`       |
| **메모리 형태**      | 단일 변수        | 배열(list, array 등) |

- **배열**: 선형 구조이면서 같은 타입만 나열한 것
- **리스트**: 선형 구조이면서 타입에 상관없이 나열한 것
