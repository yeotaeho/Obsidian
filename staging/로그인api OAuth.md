# 로그인 API — OAuth와 JWT로 보안·성능 두 마리 토끼 잡기

소셜 로그인(카카오·네이버·구글)을 OAuth로 구현하면서, JWT를 어디에 어떻게 저장해야 보안과 성능을 동시에 잡을 수 있는지 정리했습니다.

## 2. JWT를 서버에서만 저장할 때의 문제점

서버가 모든 사용자의 로그인 상태를 메모리나 DB에 들고 있는 방식(Stateful)은 다음 한계가 있습니다.

- **서버 자원 고갈:** 접속자가 많아질수록 메모리 점유율이 올라가고 DB 조회 부하가 커집니다.
- **확장성 저해:** 서버를 여러 대로 늘리면, 1번 서버에서 로그인한 유저 정보를 2번 서버가 알지 못해 별도의 공유 저장소(Redis 등)가 필요해집니다.
- **Stateless 철학 위반:** JWT는 본래 서버가 유저를 기억하지 않으려고 만든 것인데, 서버가 저장하는 순간 그 장점이 사라집니다.

> **즉, 서버가 모든 사용자 정보를 저장하면 우리 서비스의 사용자가 맞는지 일일이 확인해야 합니다.**

반대로 Refresh Token을 브라우저의 `HttpOnly` 쿠키에 저장하면, Access Token이 만료될 때마다 서버에 묻지 않고 쿠키에서 갱신할 수 있습니다. 다만 백엔드에도 Refresh Token을 저장해 둬야 하는데, 그 이유는 **로그아웃이나 해킹 위협 시 서버에서 Refresh Token을 삭제**하기 위함입니다. 그러면 재로그인 시 서버에 토큰이 없으므로 인증이 거부됩니다.

## 3. 프론트와 분담 시 해결되는 점 (Stateful → Stateless)

프론트엔드에 토큰을 넘겨주면, 서버는 '기억'의 의무에서 벗어나 '판독'의 역할만 수행합니다.

- **서버 부하 감소:** 서버는 유저 정보를 들고 있지 않고, 토큰이 "우리 서버에서 발행한 게 맞는지"만 수학적으로 검증하면 됩니다.
- **무한한 확장성:** 어떤 서버로 요청이 가더라도 같은 `Secret Key`만 있으면 즉시 인증됩니다.
- **보안과 성능의 균형:**
  - **Access Token:** 프론트(메모리)에 두어 빠른 서비스 이용 제공
  - **Refresh Token:** 브라우저(`HttpOnly` 쿠키)와 백엔드(DB/Redis)에 두어 안전한 통제권 확보

## 4. 전체 인증 흐름 (Final Flow)

### ① 최초 로그인 (인증 단계)
1. 사용자가 로그인(OAuth 등)하면 백엔드는 DB를 확인합니다.
2. 백엔드는 **Access Token(AT)** 과 **Refresh Token(RT)** 을 생성합니다.
3. **RT**는 백엔드 DB(또는 Redis)에 저장합니다(나중에 통제하기 위함).
4. 프론트엔드로 두 토큰을 보냅니다(RT는 `HttpOnly` 쿠키로, AT는 JSON 응답으로).

### ② 서비스 이용 (인가 단계)
1. 프론트는 **AT**를 Zustand 같은 메모리에 보관하며, API 요청마다 헤더에 담아 보냅니다.
2. 서버는 DB를 뒤지지 않고 `Secret Key`로 **AT**의 서명만 확인해 즉시 응답합니다.

### ③ 토큰 만료 및 갱신 (유지 단계)
1. **AT**가 만료되면 프론트가 갱신을 요청합니다.
2. 이때 브라우저가 쿠키의 **RT**를 자동으로 서버에 전달합니다.
3. 서버는 자기 DB의 **RT**와 비교해, 일치하면 새로운 **AT**를 발급합니다.

### ④ 로그아웃 (통제 단계)
1. 사용자가 로그아웃하면 백엔드는 **DB에 저장했던 RT를 삭제**합니다.
2. 이제 해커가 기존 RT를 훔쳤더라도 서버 장부에 없으므로 더 이상 AT를 재발급받을 수 없습니다.

> **서버는 "최초 확인"과 "최종 통제"만 담당하고, "일상적인 인증"은 토큰을 가진 프론트엔드가 스스로 증명하게 함으로써 효율적인 시스템이 완성됩니다.**

## 5. 용어 정리

- **Authentication(인증)** — Refresh Token
- **Authorization(권한/인가)** — 인가 코드, Access Token
- 그 외: Redirect, 토큰, PKCE

## 7. 토큰 저장 위치 정리

**프론트엔드**

- **Access Token**: 메모리(React state / 모듈 변수)에만 보관 → 페이지 새로고침하면 사라짐
- **Refresh Token**: `HttpOnly + Secure + SameSite` 쿠키로 보관

**백엔드**

- **Access Token**: Redis(Upstash)
- **Refresh Token**: Neon DB
