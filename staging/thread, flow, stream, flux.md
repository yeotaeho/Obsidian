# Thread, Flow, Stream, Flux — 흐름을 다루는 개념들

`thread`, `flow`, `stream`, `flux`는 모두 컨텍스트 안에서 **흐름(flow)** 을 의미하는 개념입니다. 처음에는 비슷해 보였지만, 동기/비동기 관점에서 정리하니 구분이 명확해졌습니다.

## 왜 비동기로 전환해야 했나

기존 구조에서는 프론트에서 값을 보내는 곳이 한 곳이었습니다. 하지만 **AI를 넣으면 값을 보내는 곳이 늘어납니다.** 그래서 동기 방식으로는 한계가 생겨, **비동기(논블로킹) Flux로 전환**해야 했습니다.

> **Stream → Flux: 게이트웨이를 논블로킹·비동기화한다.**

## 개념 정리

- **Thread**: 실행의 흐름.
- **Stream**: 동기 방식. 기존 유레카 구조에서 쓰던 흐름입니다.
- **Flow**: 모바일 환경에서의 흐름.
- **Flux**: 논블로킹(비동기). **단방향 데이터 흐름을 강제하는 아키텍처 패턴**입니다.

| 구분 | 방식 |
| --- | --- |
| 동기 / 블로킹 | Stream, Flow |
| 비동기 / 논블로킹 | Flux |

## 비동기 전환의 이점

동기 방식에서는 데이터를 주고받을 때 프론트와 백엔드의 컨텍스트가 **둘 다 켜져 있어야** 합니다. 하지만 비동기로 전환하면 **프론트 컨텍스트가 꺼져 있어도** 통신이 가능합니다.

이 차이는 `stateless`와 `stateful`의 차이로도 이어집니다.
