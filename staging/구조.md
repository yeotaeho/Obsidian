# 아키텍처 구조 고민 — 게이트웨이 분리와 프론트 분할

크게 보면 전체 구조는 `프론트 → 게이트웨이 → 서버/AI`로 이어집니다. 이 구조를 운영하기 좋게 다듬으며 했던 고민을 정리했습니다.

## 게이트웨이를 스프링 밖으로 분리

게이트웨이가 스프링 안에 들어 있었는데, **차라리 게이트웨이 폴더를 빼서 따로 관리하는 편이 낫겠다**고 판단했습니다.

## 프론트 분할 — admin / www / app

프론트도 마찬가지였습니다. 사용자 화면마다 등급에 따라 다르게 설정해야 하는데, 이를 하나로 관리하기는 어렵고 오류도 잦을 것 같았습니다. 그래서 프론트를 다음과 같이 나눴습니다.

- **admin** — 관리자
- **www** — 일반 웹
- **app** — 앱/모바일(ERP)
