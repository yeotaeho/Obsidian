# 넷플릭스 유레카 — MSA 구조와 Spring Cloud Gateway/Eureka 설정기

프로젝트를 처음 만들 때부터 **마이크로서비스(MSA) 구조**로 잡았습니다. 가장 큰 이유는 장애 격리였습니다.

> **모놀리식은 서비스 덩어리 하나가 고장 나면 전체가 멈추지만, 마이크로서비스는 서비스를 쪼개 두기 때문에 고장 난 서비스만 중지하면 됩니다.**

처음 프로젝트를 만들 때 이 구조로 잡으면, 서비스 하나하나를 분리할 수 있다는 것이 가장 큰 장점입니다. 어느 한 서비스에서 에러가 나도 그것만 중지하면 됩니다. 기존 방식에서는 이게 불가능했습니다.

## 1. 전체 구성 요소

- **로드 밸런서**: 라운드 로빈 방식으로 React와 Spring을 연결해 주는 중재자입니다.
- **엔트리포인트 — 게이트웨이 — 엣지 서버(경계선)** 로 이어지는 진입 구조를 둡니다.
- 프론트에서 게이트웨이까지 가는 것을 **HTTP**, 게이트웨이에서 컨트롤러까지 가는 것을 **라우팅**이라고 합니다.

게이트웨이는 통합적인 진입점이며, 설정 흐름은 다음과 같습니다.

```
gateway → secrets → configuration → eureka → discovery
```

- **eureka**: 서비스 검색(디스커버리). 어떤 서비스가 어디 있는지 찾아 줍니다.
- **configuration**: 구성 저장소.

## 3. build.gradle 의존성

각 모듈의 `build.gradle`도 역할에 맞게 바꿔 줘야 합니다.

```gradle
dependencies {
    implementation group: 'http://org.springframework.cloud', name: 'spring-cloud-config-server', version: '4.1.3'
    implementation group: 'org.springframework.boot', name: 'spring-boot-starter-actuator', version: '3.3.4'
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
    implementation 'http://org.springframework.cloud:spring-cloud-config-server'
    implementation 'org.springframework.boot:spring-boot-starter-actuator'
}
```

`dependencies` 내용은 프로그램(각 서비스 역할)에 맞춰 조정해야 합니다.
