## 3. 컴포넌트 — 모든 것은 컴포넌트(=객체)다

React에서는 **모든 것이 컴포넌트(객체)** 입니다. `{}`(중괄호)로 감싸져 있으면 객체라고 보면 됩니다.

상태에 따라 객체인지 아닌지가 갈립니다. 값이 들어간 상태여야 하며, 값이 들어가지 않으면 생성되지 않습니다. 컴포넌트는 클래스에 대응한다고 보면 이해가 쉽습니다.

```
function a() {}   ↔   class a {}
```

DOM 역시 `new HTML`처럼 생성되는 객체로 이해했습니다.

컴포넌트 예시는 다음과 같습니다.

```jsx
function Button({ label, onClick }) {
  return <button onClick={onClick}>{label}</button>;
}

function App() {
  return <Button label="클릭" onClick={() => alert("Hi")} />;
}
```

프론트에서 `axios`로 값을 보내면, 백엔드는 CORS(cross-origin) 설정을 통해 그 값을 받습니다.

## 4. 무상태(Stateless) — 보안 관점

프론트엔드는 구조상 보안에 취약합니다. 이 문제를 줄이기 위해 **무상태**를 적용합니다. 즉, 상태(중요 정보)를 함수가 직접 들고 있지 않게 만드는 것입니다. 그러면 해커가 들여다봐도 **기능만 보이고 중요한 정보는 보이지 않습니다.**

방법은 간단합니다. **함수 안에 변수(정보, status)를 두지 않으면 됩니다.** 상태는 인터페이스로 분리합니다.

- 스택: `Next.js + React`
- 상태 라이브러리: `zustand`
- **provider**: 스토어와 React를 연결하는 객체

## 6. state vs prop

- 컴포넌트 **안**에서는 `state`, **밖**에서는 `prop`을 씁니다. 나중에 서버 쪽으로 보낼 때는 `prop`으로 보내야 합니다.
- 둘 다 상태이지만, **state는 한 방향으로 흐르고 prop은 양방향**입니다.

## 7. Redux / 상태 관리자

`리액트(tsx) + 리덕스` 조합에서 **리덕스는 상태 관리자**입니다. 상태를 관리하고 바꾸는 역할로, 스프링의 컨텍스트와 연결해서 이해했습니다.

```bash
npx create-next-app@14 my-app --ts
```

관련 키워드로는 메모이제이션(메멘토), `callback` 등이 있습니다.

## 8. tsx 구조 — 컴포넌트 + 컨테이너

`tsx` 구조는 **컴포넌트 + 컨테이너**로 나뉩니다. 사용자가 액션을 하면 컨테이너가 핸들링하여 컴포넌트로 보내고, 컴포넌트에서 훅(use~)으로 상태를 변환한 뒤 리턴합니다. 그 결과가 다시 컨테이너로 와서 화면에 표시됩니다.

```
컨테이너 → 컴포넌트 → 컨테이너
```

## 9. 미들웨어

<!-- TODO: 이미지 업로드 필요 -->
![[Pasted image 20251121130940.png]]

미들웨어는 중간에서 데이터 흐름을 관리합니다.

> **미들웨어 = 시스템과 시스템 사이에서 공통 기능을 제공해 주는 중간 관리자.**
> **요청/응답 흐름을 가로채 처리한 뒤 다음 단계로 넘기는 기술입니다.**

DB에서 바로 프론트로 넘겨도 되는 데이터(예: 광고)는 곧장 화면으로 내보낼 수 있습니다. 미들웨어는 **언제든 설치하고 없앨 수 있다**는 점이 특징입니다.

- **레디스(Redis)**: 초고속 메모리 기반 데이터 저장소(In-memory DB)입니다. PostgreSQL처럼 중요한 정보를 담는 용도가 아니라, 바로 화면으로 보내도 될 정보나 일정 기한이 지나면 지워질 캐시성 데이터를 저장합니다.

## 10. 스토어(Store)

> **스토어 = 애플리케이션 전체의 상태를 한 곳에서 관리하는 객체.**

자바에서는 컨트롤러가 값을 전달하려면 파이프라인을 만들어야 하지만, 스토어 슬라이스는 그런 개념이 아닙니다. **어느 한 슬라이스에서 값을 만들면 모든 슬라이스에 공유**됩니다. 방향이 따로 없고 자유롭습니다. 파편화되어 있는 컨텍스트를 하나로 모으는 셈입니다.

사용자가 화면에서 액션을 취하면, 그 액션을 감지해 스토어에 JSON 형태로 상태가 저장됩니다.

- **훅(Hook)**: `use`로 시작하며, 라이브러리에서 받아온 컴포넌트에서 사용합니다. 스토어와 연결하는 역할입니다.

### tsx와 ts의 분리

- `tsx` 파일: 반드시 **훅과 return(컨테이너)** 이 있어야 합니다.
- `ts` 파일: **핸들러(이벤트 기능)** 만 담습니다. JSX 문법(`<div>`, `<Component />` 등)과 React 컴포넌트는 들어갈 수 없습니다.

기능(`ts`)과 속성(`tsx`)을 따로 쪼개고, 둘을 연결해 주는 것이 **훅**입니다.

> **JSX는 JavaScript + XML 형태의 문법으로, React에서 UI를 표현하기 위한 특별한 문법입니다.** 자바스크립트 안에서 HTML처럼 생긴 코드를 작성할 수 있게 해 줍니다.
