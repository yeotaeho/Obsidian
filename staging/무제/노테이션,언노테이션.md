# 애너테이션과 스프링 빈 — @Component, 싱글톤, 컨텍스트

스프링에서 애너테이션이 어떻게 객체를 만들고 관리하는지, 그리고 그것이 왜 인스턴스가 아니라 싱글톤 빈인지 정리했습니다.

## 1. 애너테이션(Annotation)

- **정의**: 자바에서 코드에 메타데이터(추가 정보)로 붙이는 특별한 표시입니다.
- **역할**: 코드의 의미를 보강하거나, 컴파일러/런타임에 특정 동작을 지시할 때 사용합니다.
- **문법**: `@` 기호를 사용합니다.

```java
@Override
public String toString() {
    return "Hello";
}

@Entity
public class User {
    @Id
    private Long id;
}
```

- `@Override` → 부모 클래스의 메서드를 오버라이드하고 있음을 알려 줍니다.
- `@Entity`, `@Id` → 스프링/JPA에서 DB 테이블과 매핑할 때 사용합니다.

`new` 없이 컨트롤러를 쓸 수 있는 이유는, `@Controller`가 자체적으로 `Controller ps = new ProductsController()`처럼 **application(최상위 부모 객체)에 객체를 생성**해 주기 때문입니다.

자바와 데이터베이스를 연결할 때도 애너테이션을 사용할 것입니다. 지워지지 않는 객체이기 때문에, 스프링을 이용해 만듭니다.

**싱글톤(Singleton)**
> 어떤 클래스의 인스턴스가 **오직 하나만 생성**되도록 보장하고, 그 인스턴스를 **전역적으로 접근**할 수 있게 제공하는 디자인 패턴입니다.

## 3. 생성자 애너테이션

- `@NoArgsConstructor`: 빈 깡통(`class PickProEntity()`)으로, 값을 넣을 수 있습니다.
- `@AllArgsConstructor`: 처음부터 값이 들어가 있는 깡통(`class PickProEntity(indexId)`)으로, 값이 정해진 상태라 수정이 불가합니다.

## 4. @CrossOrigin

`@CrossOrigin`은 origin을 서로 교차(연결)시킵니다. 여기서 origin은 URL, 즉 출처라고 생각하면 됩니다.

## 5. 스프링 빈과 컨텍스트

> **스프링이 직접 생성해 컨테이너에 등록한 객체만 스프링 빈입니다.**

> **스프링 컨텍스트는 스프링 빈을 만들고 관리하는 큰 환경(저장소)이며, 그 안에 스프링이 직접 생성하여 등록한 객체만 스프링 빈입니다.**

컨텍스트는 프레임워크마다 형태가 다릅니다.

- **Java/Spring**: `ApplicationContext` → 스프링이 관리하는 빈들의 집합과 설정 정보
- **JPA**: `Persistence Context` → 엔티티 객체들을 관리하고 DB와 동기화하는 환경
- 유레카에도 유사한 개념이 있습니다.

## 6. @Component와 그 자식들

`@Component`는 스프링에서 다음 애너테이션들을 자동으로 생성·관리합니다(흐름: `컨 → 서 → 레 → 엔`).

- `@Controller`
- `@Service`
- `@Repository`
- `@Entity`

또한 `@Bean`은 Config와 연결할 때 사용합니다.
