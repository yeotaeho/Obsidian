# RE100 팀 프로젝트(예창패) — 에너지 최적화 시스템과 IFRS ESG 보고서 자동화 에이전트

예비창업패키지 팀 프로젝트로 진행한 두 축을 정리했습니다. 하나는 **잉여 재생에너지를 수소·바이오차·배터리로 최적 배분하는 의사결정 시스템**이고, 다른 하나는 **IFRS 지속가능성 공시 보고서를 자동 생성하는 멀티 에이전트**입니다.

# Part 1. RE100 에너지 최적화 시스템

## 1. 핵심 의사결정

AI 에이전트가 매 시점 잉여 전력을 어떻게 쓸지 결정합니다. 액션은 `PRODUCE_H2`(수소 생산), `SELL_POWER`(전력 판매), `PRODUCE_BIOCHAR`(바이오차 생산), `STORE_BATTERY`(배터리 저장), `IDLE` 중 하나이며, **예상 수익(`expected_profit`)을 최대화**하는 방향으로 선택합니다.

## 2. 데이터베이스 스키마

도메인별 Base를 분리(`ai_bases`, `greenh2_bases`, `biochar_bases`, `re100_bases`)했고, 주요 테이블은 다음과 같습니다.

### 2.1. 의사결정 결과 — `optimization_results` (AI 도메인)
AI 에이전트의 최적화 의사결정 결과를 저장합니다.

```python
class OptimizationResult(Base):
    __tablename__ = "optimization_results"

    id = Column(Integer, primary_key=True, index=True, autoincrement=True)
    timestamp = Column(DateTime, nullable=False, index=True)
    region_code = Column(String(10), nullable=True)

    # 의사결정 결과
    action = Column(String(20), nullable=False)        # "PRODUCE_H2", "SELL_POWER", "IDLE"
    expected_profit = Column(Float, nullable=False)    # 예상 수익 (원)

    # 계산된 값
    usable_mw = Column(Float, nullable=True)           # 사용 가능한 전력 (MW)
    h2_production_kg = Column(Float, nullable=True)     # 수소 생산량 (kg)
    carbon_reduction_kg = Column(Float, nullable=True) # 탄소 감축량 (kg)

    # 수익 구성
    h2_sales_revenue = Column(Float, nullable=True)    # 수소 판매 매출
    carbon_value = Column(Float, nullable=True)        # 탄소 가치
    subsidy_revenue = Column(Float, nullable=True)     # 보조금
    power_sell_revenue = Column(Float, nullable=True)  # 전력 판매 수익
    total_cost = Column(Float, nullable=True)          # 총 비용

    # 입력 데이터 (참고용)
    smp_price = Column(Float, nullable=True)           # 계통한계가격 (원/kWh)
    h2_price = Column(Float, nullable=True)            # 수소 판매가격 (원/kg)
    surplus_mw = Column(Float, nullable=True)          # 잉여전력 (MW)
    carbon_credit_price = Column(Float, nullable=True) # 탄소배출권 가격 (원/tCO2eq)
```

추가로 `decision_*`(4가지 옵션 분배 비율), `score_*`(옵션 점수), `value_*`(옵션 가치), `carbon_impact_*`(탄소 영향), `previous_action`/`current_runtime_hours`(시스템 상태 추적) 필드를 둡니다.

### 바이오차 전환율 계산 (논문 기반)

고정값(30%) 대신 원료·공정 조건을 반영해 정확도를 높였습니다.

- **원료별 기본 수율**: 산림 부산물 40%, 농업 부산물 32%, 음식물 쓰레기 35%, 가축분뇨 30%, 해조류 28%, 감귤박 25%
- **공정 조건 보정**: 온도(500°C 기준), 체류 시간(30분 기준), 가열 속도(10°C/min 기준), 수분 함량
- 최적화 에이전트(`h2_optimization_agent.py`)에서 논문 기반 계산을 사용하고, 실패 시 고정값으로 폴백

| 방법 | 정확도 | 설명 |
| --- | --- | --- |
| 기존 (고정값 30%) | 60-70% | 원료/조건 무시 |
| 논문 기반 계산 | 75-85% | 원료/온도/시간 등 반영 |
| 실제 플랜트 데이터 | 90-95% | 실제 운영 값 |

# Part 2. IFRS ESG 보고서 자동화 에이전트

GRI/SASB/TCFD 기반 데이터를 IFRS S2 스타일 공시 문단으로 변환·생성하는 멀티 에이전트입니다.

## 1. 참조 기준서

| 기준서 | 핵심 문서 |
| --- | --- |
| **IFRS S2** | Climate-related Disclosures (2023) — 가장 중요 |
| **IFRS S1** | General Requirements for Disclosure of Sustainability-related Financial Information |
| **GRI** | GRI 305: Emissions 2016, GRI 102 Climate Change 2025, GRI 103 Energy 2025 |
| **TCFD** | 2017 Recommendations Report, 2021 Implementing Guidance |
| **SASB** | 77개 산업별 표준 (IFRS 산하, navigator.sasb.ifrs.org) |

추천 사용 순서: **IFRS S2 → GRI 305 → TCFD → SASB Navigator.**

## 2. 데이터 소싱 전략

- **Supervisor(감사관)**: 학습이 아니라 "지식 주입"(프롬프트). IFRS 기준서에서 추출한 판단 기준(Rule-book), 워크플로우 로직, 검토 가이드라인(Rubric), Few-shot 예시로 구성. Rubric은 약 100~200개 규칙(JSON 형태). 한국 공시 기준(K-IFRS, KASB)도 추가.
- **Gen Node(생성)**: EXAONE 3.0 7.8B를 LoRA로 학습하므로 **instruction-input-output 쌍** 데이터셋이 핵심. DART의 기업 지속가능성 보고서(GRI/TCFD 기반)를 IFRS S2 스타일로 변환해 500~1000개 쌍 구성.
- **통합**: 기업 내부 데이터(DART PDF)와 기준서(IFRS PDF)를 RAG로 결합. 멀티모달(표·차트) 처리 시 PDF 내 표/이미지 추출. **공공 PDF만 사용, 저작권 준수.**

## 3. 오케스트레이터 아키텍처

두 구성 요소로 나뉩니다.

- **SupervisorAgent(감사관)**: 워크플로우 제어와 품질 검수. 모델은 Llama 3.3 70B(Groq). `analyze() → review() → audit()` 3단계.
- **IFRSAgentWorkflow**: LangGraph `StateGraph`로 노드 연결·실행. 조건부 엣지로 반복 루프 구현.

### 3.2. SupervisorAgent — 3단계 프로세스

```python
class SupervisorAgent:
    """감사관 페르소나 - 워크플로우 제어"""

    def __init__(self, llm_client: GroqClient):
        self.llm = llm_client
        self.rulebook = self._load_rulebook()

    def analyze(self, state: IFRSAgentState) -> IFRSAgentState:
        """1단계: 사용자 요청 분석 및 필요 DP 식별"""
        prompt = self._build_analysis_prompt(state["query"], state["target_standards"])
        response = self.llm.generate(prompt)
        decision = self._parse_decision(response)
        state["target_dps"] = decision["required_dps"]
        state["current_node"] = "analyzing"
        state["audit_log"].append({"action": "analyze", "decision": decision, "timestamp": datetime.now()})
        return state

    def review(self, state: IFRSAgentState) -> IFRSAgentState:
        """2단계: RAG 추출 결과 검토"""
        required_dps = set(state["target_dps"])
        extracted_dps = set(fs["dp_id"] for fs in state["fact_sheets"])
        missing = required_dps - extracted_dps
        state["current_node"] = "reviewing"
        state["audit_log"].append({"action": "review", "missing_dps": list(missing), "timestamp": datetime.now()})
        return state

    def audit(self, state: IFRSAgentState) -> IFRSAgentState:
        """3단계: 생성 결과 최종 감사"""
        validation_result = state["validation_results"][-1]

        # 그린워싱 체크
        if validation_result["greenwashing_risk"] > 0.7:
            state["audit_log"].append({"action": "reject", "reason": "greenwashing_risk", "timestamp": datetime.now()})
            return state

        # IFRS 준수 체크
        if validation_result["compliance_score"] < 0.8:
            missing_dps = self._identify_missing_dps(state["generated_sections"], state["target_dps"])
            state["audit_log"].append({"action": "request_revision", "missing_dps": missing_dps, "timestamp": datetime.now()})

        state["current_node"] = "auditing"
        return state
```

### 3.3. LangGraph 워크플로우와 조건부 루프

```python
class IFRSAgentWorkflow:
    def _build_graph(self) -> StateGraph:
        workflow = StateGraph(IFRSAgentState)

        # 노드 등록 (Supervisor 메서드를 노드로)
        workflow.add_node("supervisor_analyze", self.supervisor.analyze)
        workflow.add_node("rag_node", self.rag_node.process)
        workflow.add_node("supervisor_review", self.supervisor.review)
        workflow.add_node("gen_node", self.gen_node.process)
        workflow.add_node("validation_node", self.validation_node.process)
        workflow.add_node("supervisor_audit", self.supervisor.audit)

        # 순차 엣지
        workflow.set_entry_point("supervisor_analyze")
        workflow.add_edge("supervisor_analyze", "rag_node")
        workflow.add_edge("rag_node", "supervisor_review")

        # 조건부 엣지: 데이터 충분성 → 재검색 또는 진행
        workflow.add_conditional_edges(
            "supervisor_review", self._check_data_sufficiency,
            {"rag_node": "rag_node", "gen_node": "gen_node"})

        workflow.add_edge("gen_node", "validation_node")
        workflow.add_edge("validation_node", "supervisor_audit")

        # 조건부 엣지: 최종 감사 → 재생성 또는 완료
        workflow.add_conditional_edges(
            "supervisor_audit", self._check_quality,
            {"gen_node": "gen_node", "end": END})

        return workflow.compile()

    def _check_data_sufficiency(self, state) -> str:
        missing = set(state["target_dps"]) - set(fs["dp_id"] for fs in state["fact_sheets"])
        if missing and state["iteration_count"] < 3:
            state["iteration_count"] += 1
            return "rag_node"   # 재검색
        return "gen_node"

    def _check_quality(self, state) -> str:
        if not state["validation_results"]:
            return "end"
        latest = state["validation_results"][-1]
        if latest.get("greenwashing_risk", 0) > 0.7:
            return "end"        # 거부
        if latest.get("compliance_score", 1) < 0.8 and state["iteration_count"] < 3:
            state["iteration_count"] += 1
            return "gen_node"   # 재생성
        return "end"
```

그래프 흐름은 다음과 같습니다.

```
Entry → supervisor_analyze → rag_node → supervisor_review
  ├─[데이터 부족]→ rag_node (재검색)
  └─[충분]→ gen_node → validation_node → supervisor_audit
        ├─[품질 미달]→ gen_node (재생성)
        └─[통과]→ END
```

> **핵심 설계 원칙: 관심사 분리(상태/감사관/워크플로우), 확장성(`set_nodes()`로 노드 교체), 타입 안정성(TypedDict·Pydantic), 에러 처리·로깅, 테스트 용이성(더미 노드·동기 실행).**

## 5. 기준서 DP 추출 CLI

기준서 PDF에서 Data Point를 추출해 임베딩까지 생성하는 스크립트입니다. **프로젝트 루트(`ifrsseed`)에서 실행**합니다.

```bash
# IFRS S2 (기본 실행, 임베딩 포함)
python -m ifrs_agent.scripts.extract_dps_from_standards \
    ifrs_agent/data/issb-2023-a-ifrs-s2-climate-related-disclosures.pdf --standard IFRS_S2

# LLM 보조 한국어 이름 추출
python -m ifrs_agent.scripts.extract_dps_from_standards \
    ifrs_agent/data/issb-2023-a-ifrs-s2-climate-related-disclosures.pdf --standard IFRS_S2 --use-llm

# 임베딩 생성 없이 (빠른 테스트)
python -m ifrs_agent.scripts.extract_dps_from_standards \
    ifrs_agent/data/issb-2023-a-ifrs-s2-climate-related-disclosures.pdf --standard IFRS_S2 --no-embeddings

# TCFD (PyMuPDF 강제)
python -m ifrs_agent.scripts.extract_dps_from_standards \
    ifrs_agent/data/FINAL-2017-TCFD-Report.pdf --standard TCFD --parser pymupdf

# GRI (LLM 보조)
python -m ifrs_agent.scripts.extract_dps_from_standards \
    "ifrs_agent/data/GRI 102_ Climate Change 2025.pdf" --standard GRI --use-llm
```

| 옵션 | 설명 | 기본값 |
| --- | --- | --- |
| `--standard` | 기준서 코드 (IFRS_S1, IFRS_S2, GRI, TCFD, SASB) | IFRS_S2 |
| `--use-llm` | LLM 보조 한국어 이름 추출 (Groq API 필요) | False |
| `--no-embeddings` | 임베딩 생성 안 함 (빠른 테스트) | False |
| `--parser` | 파서 선택 (pymupdf, llamaparse, unstructured) | 자동 |

> **주의: `--use-llm`은 `GROQ_API_KEY` 필요. DB에 이미 존재하는 DP는 `dp_id`/`dp_code` 기준으로 중복 저장되지 않음. 임베딩 생성은 BGE-M3 로딩 포함으로 시간이 걸릴 수 있음.**

## 6. GRI 표준 — 필요한 것만 받기

GRI Full set ZIP은 44개 이상 PDF로 방대하지만, **기후 전환(GRI → IFRS S2) 중심 프로젝트라 전부 필요하지는 않습니다.** 다음 5~6개만 받으면 90% 이상 커버됩니다.

1. **GRI 102: Climate Change 2025** — 가장 중요(기후 적응·완화, 전환 계획, 시나리오 분석). Gen Node 학습 데이터로 최적
2. **GRI 103: Energy 2025** — 에너지 소비·재생에너지 전환(GRI 302 대체)
3. **GRI 305: Emissions 2016** — Scope 1/2/3 배출량 정의·측정·공시(여전히 핵심)
4. **GRI 302: Energy 2016** — 이전 보고서 비교용(필요 시)
5. **Universal Standards 3종** — GRI 1 Foundation, GRI 2 General Disclosures, GRI 3 Material Topics (거버넌스·물질성)
6. **Glossary** — 임베딩 튜닝 시 ESG 용어 Positive/Negative Pair 생성에 유용

다운로드는 GRI 공식 페이지에서 위 파일만 개별로 받는 편이 ZIP 전체보다 관리가 쉽습니다.
